3. FORMULA TIMER - FUENTE UNICA (DE OPENCODE)

apps/cajero/lib/time.ts -> getStartTime()

startEfectivo = max(acceptedAt ?? createdAt, scheduledFor - estimado - buffer30min)

Si now < startEfectivo => delay = -1 (verde, no rojo)
Si now >= startEfectivo => delay empieza a contar

Misma formula en telegram-alert.ts para no alertar antes.

4. FLUJO UI COMPLETO

A) CREAR RESERVA:
Checkbox [ ] Es Reserva? -> DateTime picker "Para cuando?"
Al guardar: scheduledFor=20:00, reservationConfirmed=false, stockReserved=false, NO descuenta stock, NO imprime.

B) 3 PESTAÑAS:
1. RESERVAS (arriba, azul) - Card gris "Reserva 20:00 - Juan - Falta 5h 12m"
2. EN PRODUCCION - Solo inmediatos + reservas confirmadas
3. ENTREGADOS / CANCELADOS

C) VENTANA 30min ANTES:
- Card amarilla -> roja parpadeante + sonido reserva.mp3
- Boton grande: [CONFIRMAR Y PASAR A COCINA]
  Al confirmar: reservationConfirmed=true, acceptedAt=now(), stockReserved=true (descuenta stock), mueve a EN_PRODUCCION, imprime en CAJA (o genera PNG virtual), cajero lleva papel a cocina.

5. CANCELACION - PARA QUE NO QUEDEN PRODUCTOS EN DB

Caso 1 - ANTES de confirmar (14:00 cancela reserva 20:00):
  stockReserved=false, no devuelve nada.
  UPDATE status=CANCELADO, cancelledAt=now(), motivo, cancelledBy
  Desaparece de RESERVAS por filtro where status != CANCELADO

Caso 2 - DESPUES de confirmar (ya en EN_PRODUCCION):
  releaseStock(order) -> devuelve stock
  UPDATE status=CANCELADO

Caso 3 - Limpieza fisica:
  Job mensual DELETE de CANCELADOS >30 dias. Gracias a onDelete:Cascade se borran Order + OrderItems juntos, sin huerfanos.
