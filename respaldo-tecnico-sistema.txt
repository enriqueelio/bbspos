Order  (MODELO CENTRAL)
  id               String         @id @default(cuid())

  total            Int

2.2 MAPA DE RELACIONES
-----------------------
User 1──→N Order            (via userId — quien creo/ato el pedido)
User 1──→N Order            (via canceledById — quien anulo, @relation "OrderCanceledBy")
User 1──→N Order            (via discountedById — quien desconto, @relation "OrderDiscountedBy")
Size 1──→N DrinkPrice       (via sizeId, onDelete Cascade)
BobaType 1──→N DrinkPrice   (via bobaTypeId, onDelete Cascade)
Order 1──→N OrderItem       (via orderId, onDelete Cascade)
OrderItem 1──→N OrderItemTopping (via orderItemId, onDelete Cascade)
Flavor M──→N FlavorCategory (via FlavorCategoryLink pivote, @@unique)

Sin self-references.

Patron de desnormalizacion:
  OrderItem almacena sizeName, flavorName, flavorCategory, bobaTypeName como strings
  (snapshot del catalogo al momento del pedido, NO como FK).
  OrderItemTopping almacena toppingName como string (NO FK a Topping).

4.1 LOGICA DE ZONA HORARIA (America/La_Paz)
-------------------------------------------
Zona horaria: America/La_Paz (UTC-4 fijo, SIN horario de verano)
Ni moment.js, ni date-fns, ni luxon — solo Intl.DateTimeFormat nativo

Constantes:
  packages/types/src/index.ts:
    BUSINESS_TIME_ZONE = "America/La_Paz"
    MANUAL_REPORT_CUTOFF = "23:10"
    MANUAL_REPORT_CUTOFF_MINUTES = 23 * 60 + 10

Helpers principales:
  packages/db/src/daily-report.ts:
    - zonedDateKey(date)       → "YYYY-MM-DD" en America/La_Paz
    - zonedMinutes(date)       → minutos del dia en la zona
    - shiftDayKey(date)        → dia clave segun turno (manana/tarde)
    - targetReportDate()       → fecha objetivo del reporte
    - zonedStartOfDay(date)    → medianoche local via offset fijo -4h

  apps/admin/lib/reports/range.ts:
    - REPORT_TIMEZONE = "America/La_Paz"
    - tzOffsetMs      → offset en milisegundos (-4 * 3600 * 1000)
    - getZonedParts   → year/month/day/hour/minute/second en la zona
    - zonedToUtc      → convierte hora local a UTC
    - dayBounds       → [inicio UTC, fin UTC] de un dia local
    - rangeBounds     → bounds para un rango de fechas
    - dayKeyOf        → "YYYY-MM-DD" de un Date en la zona
    - monthKeyOf      → "YYYY-MM"
    - isoWeekKeyOf    → "YYYY-Wxx"
    - hourOfDay       → hora 0-23 en la zona
    - weekdayIndex    → 0-6 (domingo=0)

  apps/cajero/lib/day.ts:
    - TIME_ZONE = "America/La_Paz"
    - localDayKey(date)     → "YYYY-MM-DD"
    - todayKey()            → dia actual
    - zonedStartOfDay(date) → midnight local via UTC - 4h
    - dayBounds(date)       → [startOfDay UTC, endOfDay UTC]

  packages/types/src/index.ts:
    - zonedClockMinutes(date, tz) → minutos del dia via Intl

Funcionamiento:
  - Fechas almacenadas en UTC en SQLite (Prisma DateTime)
  - Todas las queries de reportes usan dayBounds() para filtrar por dia local
  - El API dashboard-summary usa Intl.DateTimeFormat("en-CA", {timeZone}) para todayLocal()
  - No hay conversion risky: offset fijo -4h documentado con comentarios

4.2 IMPRESION TERMICA
---------------------
Mecanismo: PowerShell + System.Drawing.PrintDocument (Windows-only, NO usa escpos)
No hay paquete npm de impresion — todo es nativo via spawn de powershell.exe

Configuracion compartida:
  apps/store/printing.json (gitignored) — { "printerName": "..." }
  Todas las apps leen este archivo:
    apps/store/lib/printing.ts   → join(process.cwd(), "printing.json")
    apps/cajero/lib/printing.ts  → join(process.cwd(), "..", "store", "printing.json")
    apps/mesero/lib/printing.ts  → join(process.cwd(), "..", "store", "printing.json")
    apps/admin/lib/printing.ts  → join(process.cwd(), "..", "store", "printing.json")

Funcionamiento del nucleo (printText):
  1. getPrinterName() lee printing.json
  2. runPowerShell(script) — timeout 15s, spawn powershell.exe -NoProfile -NonInteractive
  3. printText(printerName, text):
     - Base64-encodes UTF-8 text
     - Divide en lineas, calcula largo maximo
     - Mide ancho de caracter con Consolas 12pt bold
     - Auto-dimensiona font: size = Min(12, availW/(maxLen*cw)*12)
     - Papel ~80mm (300-340 unidades de ancho)
  4. toAscii(text) — elimina acentos (á→a, ñ→n, etc.) por compatibilidad termica

Formato de comanda:
  - Header: "BUBBLE DRINK"
  - Titulo: "COMANDA #seq"
  - Ancho: 34 columnas
  - Abreviaturas: Grande→G, Extragrande→XG, Tapioca→Tap, Explosivas→Expl
  - Filas con puntos de relleno hasta el precio
  - Fecha: toLocaleString("es-BO", {dateStyle, timeStyle})

Gestion de impresora (admin):
  - connectSharedPrinter(uncPath) → Add-Printer -ConnectionName '\\EQUIPO\Printer'
  - listPrinters() → Get-CimInstance Win32_Printer (nombre, default, offline)
  - setPrinterConfig(printerName) / getPrinterConfig() → escritura/lectura del JSON
  - formatTestPage(printerName) → pagina de prueba diagnostica
  - API routes: /api/printer, /api/printer/connect, /api/printer/test
  - UI: apps/admin/(dashboard)/printer/page.tsx

Donde se imprime:
  - Store: al crear pedido (Next.js after(), best-effort, no bloquea)
  - Cajero: al crear pedido POS (try/catch, non-blocking)
  - Mesero: al crear pedido POS (try/catch, non-blocking)
  - Cajero reprint: reprintOrder(orderId) solo si RECIBIDO/ACEPTADO
  - Cajero reporte: printDailyReport() — reporte personal diario
  - Admin: printSummaryReport() y printDailyReport(date)

4.3 CIERRE DIARIO AUTOMATICO A TELEGRAM
----------------------------------------
Mecanismo: 2 workers Node.js con loop setInterval(60s) en el contenedor Docker
No hay cron del SO — todo corre internamente en el container

A. REPORTE DIARIO DE CIERRE

  Fuente: packages/db/src/daily-report.ts (341 lineas)
  Worker:  packages/db/scripts/daily-report-worker.ts

  collectReportStats(key):
    - Revenue de pedidos entregados + avg ticket + desglose por metodo de pago
      (incluye split payments: total-amount2 para method1, amount2 para method2)
    - Tiempo promedio de entrega (deliveredAt - createdAt)
    - Hora pico de revenue
    - Perdidas: anulaciones, descuentos, revenue de toppings
    - Total de pedidos, pendientes, etc.

  buildReportMessage(key, stats):
    - Markdown: "CIERRE DIARIO BIBOSI"
    - Secciones: FINANZAS / OPERACION / FUGAS Y ALERTAS
    - Montos en Bs (Bolivianos)

  sendDailyReportToTelegram(key):
    - Verifica DailyReportLog (si ya fue enviado, no reenvia — anti-duplicado)
    - POST a https://api.telegram.org/bot<TOKEN>/sendMessage
    - Envia DailyReportLog en exito

  Worker loop (daily-report-worker.ts):
    - Intervalo: 60 segundos
    - Calcula fecha objetivo: dia actual si ya paso DAILY_REPORT_HOUR, sino dia anterior
      (recupera dias perdidos si el container estuvo caido)
    - Flags CLI: --date=YYYY-MM-DD (envio especifico), --dry-run=YYYY-MM-DD (sin enviar)
    - Soporte en pnpm: pnpm daily-report (root) → pnpm --filter @bubba/db daily-report

  Triggers manuales (habilitados solo despues de 23:10):
    - Cajero: apps/cajero/app/actions/report.ts → sendDailyReportToBot()
      UI: apps/cajero/components/report-actions.tsx (boton "Enviar a Telegram")
    - Admin: apps/admin/app/actions/daily-report.ts → sendDailyReportToBot()
      UI: apps/admin/(dashboard)/reports/reports-client.tsx (boton "Cierre diario")
      Gating: canSendCierre basado en zonedClockMinutes >= MANUAL_REPORT_CUTOFF_MINUTES

  Configuracion:
    DAILY_REPORT_HOUR = "23:20" (hora de envio automatico)
    MANUAL_REPORT_HOUR = "23:10" (hora minimo para envio manual)

B. ALERTA DE PEDIDOS ATRASADOS

  Fuente: packages/db/src/telegram-alert.ts
  Worker:  packages/db/scripts/telegram-alert-worker.ts

  checkDelayedOrders():
    - Query: delayNotified=false, paidAt=null, creado hace > DELAY_ALERT_MINUTES
      y (status=ACEPTADO sin entregar O status=ENTREGADO sin pagar → "caja leak")
    - Anti-spam atomico: prisma.order.updateMany({where: {id, delayNotified: false},
      data: {delayNotified: true}}) — solo un worker envia por pedido
    - Si falla Telegram, resetea delayNotified=false para reintento

  sendAlert(seq, name, minutes, status):
    - Markdown: "PEDIDO ATRASADO" con numero de ticket, nombre cliente,
      minutos de atraso y estado
    - parse_mode: "Markdown"

  Worker loop (telegram-alert-worker.ts):
    - Intervalo: 60 segundos
    - Flag CLI: --once (una sola pasada)
